# ColorHunt iOS リリース完全ガイド

初リリース向けに「今日から審査提出まで」を1本にまとめたガイドです。
対象: iOS 16〜26 / 開発機は新しい MacBook（Apple Silicon）+ Xcode 26。

## 1. 新しい Mac の環境構築

1. **Xcode 26** を App Store からインストール（初回起動で追加コンポーネント許可）
2. **JDK 17**（KMP 共有モジュール用）: `brew install temurin@17`
3. リポジトリを clone し、ルートで一度:
   ```bash
   ./gradlew :shared:embedAndSignAppleFrameworkForXcode || true
   ./gradlew :shared:compileKotlinIosArm64   # K/N ツールチェーン初回DL
   ```
4. Xcode プロジェクト（ColorHunt）を開き、以下を確認:
   - Minimum Deployments = **iOS 16.0**
   - Run Script（shared フレームワーク埋め込み）のパスが新環境の実パスか
   - Framework Search Paths が `shared/build/xcode-frameworks/...` を指すか
   - Info.plist: `NSPhotoLibraryUsageDescription` / `NSPhotoLibraryAddUsageDescription`
     / `NSCameraUsageDescription`（ハントカメラ）
   - Localizations: en / ja / ko / zh-Hans が登録済みか
5. **Xcode 26 でのモダン化（任意・推奨）**: iOS 26 実機/シミュレータでは
   システム部品が自動で Liquid Glass 化。独自ガラスは `#available(iOS 26)` で
   追加予定（コードは iOS 16 フォールバック前提で設計済み）

### 3.4 メモリ実測（提出前の必須ゲート）

#### なぜ測る必要があるのか

ハントに取り込んだ写真は、**全てデコード済みの `UIImage` としてメモリに常駐**します
（`AppState.photos`）。1枚あたり最大 1200×1200×4バイト ≒ **5.5MB**。200枚なら
**900MB 前後**に達します。

iOS はアプリのメモリ使用量が端末ごとの上限を超えると、**警告なしで強制終了**します
（jetsam）。クラッシュログには何も残らず、ユーザーからは「突然落ちるアプリ」に
見えます。上限の目安:

| 端末 | 搭載RAM | アプリの上限（目安） | 200枚の見込み |
|---|---|---|---|
| iPhone 8 / SE(2nd) | 2〜3GB | 約 1.2〜1.4GB | **危険** |
| iPhone 11 / 12 | 4GB | 約 2GB | 注意 |
| iPhone 15 / 17 Pro | 8GB | 約 3GB〜 | 余裕 |

**最新機だけで確認しても意味がありません。** 対応下限を iOS 16 にしている以上、
2〜3GB 機で落ちないことを確認する必要があります。

#### 準備（ここを間違えると測定値が無意味になります）

1. **実機で測る。シミュレータは不可**
   シミュレータは Mac の RAM を使うため上限が事実上無く、jetsam も起きません。
   数百MB 超過していても平然と動いてしまいます。

2. **Release ビルドで測る**
   Xcode → Product → Scheme → **Edit Scheme…** → 左の **Run** → Info タブ →
   **Build Configuration** を `Debug` から **`Release`** に変更。
   Debug ビルドは最適化が無効で実際より多くメモリを使うため、Debug のまま測ると
   不必要に厳しい判定になります。
   > 測り終えたら **必ず `Debug` に戻してください**。忘れるとブレークポイントが
   > 効かなくなり、後で原因不明の「デバッグできない」状態に悩むことになります。

3. **一番古い実機を使う**
   手元に 2〜3GB 機が無い場合の代替は「#### 古い実機が無い場合」を参照。

4. **クリーンな状態から始める**
   端末からアプリを削除 → 再インストール。前回のハントデータが残っていると
   取り込み枚数が変わり、比較できません。

#### 測定手順

**A. Memory Gauge で全体像を見る（まずこれ）**

1. Xcode から実機に Run（Release 構成）
2. Xcode 左ペインの **Debug navigator**（⌘7）→ **Memory** をクリック
3. 右側に実時間のグラフと現在値が出ます。ここの数値が **footprint**（＝iOS が
   jetsam の判定に使う値）です
4. アプリを操作しながら、下の順で**各段階の数値を記録**します

| # | 操作 | 記録する値 | 目安 |
|---|---|---|---|
| 1 | 起動直後・ハント空 | ベースライン | 50〜80MB |
| 2 | 「自動で仕分け」→ 200枚取り込み完了 | **取込ピーク** | ここが最大になりがち |
| 3 | ハント画面を一番下までスクロール | 全サムネ描画後 | |
| 4 | 20枚選択 → コラージュ画面へ | | |
| 5 | Pro テンプレで **2160px 書き出し** | **書き出しピーク** | 一時的に跳ねます |
| 6 | 書き出し後、10秒待つ | 落ち着いた値 | 2 と同程度に戻るはず |

5. **さらに重要: アプリを一度終了して測り直す**
   アプリスイッチャーから完全に終了 → 再起動 → **ハント画面を最下部まで
   スクロール** → もう一度 Memory Gauge を確認。
   > 再起動直後は写真がディスクから遅延読み込みされるため、**スクロールするまで
   > 数値が低く出ます**。ここを飛ばすと「大丈夫だった」と誤判定します。
   > スクロールし切った後の値が、実際の常用時の値です。

**B. 上限までの残量を数値で見る（確実な方法）**

Memory Gauge は「今いくつ使っているか」は分かりますが「あと何MB で落ちるか」は
分かりません。それを直接測るのが `os_proc_available_memory()` です。

`ColorHuntApp.swift` の `RootTabView.body` の末尾に、以下を**一時的に**貼ります
（測定用。**測り終えたら消してください**。`#if DEBUG` 付きですが v1.0 は凍結済み
のためコミットしない運用にします）。

```swift
#if DEBUG
.onReceive(Timer.publish(every: 2, on: .main, in: .common).autoconnect()) { _ in
    let remain = Double(os_proc_available_memory()) / 1_048_576
    print(String(format: "🧠 残り %.0f MB", remain))
}
#endif
```

ファイル冒頭に `import os` が必要です。Xcode のコンソールに 2秒ごとに
「あと何MB でアプリが強制終了されるか」が出ます。

**この残量が 200MB を切ったら、その端末では落ちる寸前です。**

#### 判定

**B の「残量」** を基準に判断してください（A の絶対値より信頼できます）。
最も厳しい段階（通常は 200枚取込直後、または 2160px 書き出し中）の値で判定します。

| 残量 | 判定 | 対応 |
|---|---|---|
| **500MB 以上** | 合格 | そのまま v1.0 をリリース |
| 250〜500MB | 要注意 | リリース可。ただし v1.1 でサムネイル分離を最優先 |
| **250MB 未満** | **不合格** | **リリース前に改修が必要**（下記） |

Memory Gauge の絶対値だけで見る場合の代替基準は **700MB**。これを超えたら
2〜3GB 機で落ちると考えてください。

#### 不合格だった場合の改修（半日程度）

サムネイルと原寸を分離します。方針:

1. `HuntPhoto` に `thumbnail: UIImage`（長辺 300px 程度）を持たせ、**一覧・グリッド・
   マップのピンはサムネイルだけを描画**する
2. 原寸は常駐させず、`Documents/HuntStore/` の JPEG から**必要な時だけ読む**
   （トリミング編集を開いた時・コラージュ書き出し時）
3. 読んだ原寸は `NSCache` に入れ、メモリ警告で自動的に捨てさせる

これで常駐分が 200枚 × 約0.35MB ≒ **70MB** まで下がります。

#### 古い実機が無い場合

2〜3GB 機が手元に無い場合、次のいずれかで代替できます。

- **Instruments の Allocations で絶対値を確認する**
  Xcode → Product → **Profile**（⌘I）→ **Allocations** → Record。
  実機なら「Persistent Bytes」でどのオブジェクトが常駐しているか内訳が見えます。
  `UIImage` / `CGImage` の合計が支配的なら想定どおりです。
- **上の判定表の 700MB 基準で、手持ちの最新機で測る**
  footprint はどの端末でもほぼ同じなので、**使用量は最新機で測っても同じ値**です。
  変わるのは「上限」だけ。つまり最新機で 700MB を超えていたら、古い端末では
  落ちると判断できます。**この方法で十分に判定できます。**
- **メルカリ等で iPhone 8 / SE(2nd) を調達する**（1万円前後）
  今後も長く必要になるので、本気で世界展開するなら持っておく価値はあります。

>

## 4. TestFlight（知人配信）

1. App Store Connect → My Apps → ＋ → New App（Bundle ID は Xcode と一致）
2. Xcode: Product → **Archive** → Distribute → **TestFlight & App Store**
3. App Store Connect → TestFlight タブ → ビルドが処理完了後:
   - **Internal Testing**: 自分（最大100人・審査なし・即配信）
   - **External Testing**: 知人のメール招待（最初の1回だけ軽い審査・最大1万人）
4. 知人は TestFlight アプリから招待コードでインストール
5. フィードバックは TestFlight のスクショコメント機能で回収可能

> 以後は Archive → Upload するだけで自動的にテスターへ新ビルドが届きます。

### Step 0. 承認待ちの今やること（1〜2日）

承認前でも進められる準備です。ここを済ませておくと承認後が一気に短縮できます。

**0-1. 課金プロダクトID（対応済み・確認のみ）**

コードの製品IDは Bundle ID の接頭辞に揃えて **`com.yk-dev.ColorHunt.pro`**
にしてあります（`AppState.swift` の `proID`）。

- Step 4 で App Store Connect に登録するときは、**この文字列を1文字違わず**
  入力してください。違うと購入画面が「製品情報を読み込めませんでした」になります

**0-2. iPhone 専用に絞る（推奨・15分）**

現在は iPhone / iPad / Vision Pro 向けにビルドされています（`TARGETED_DEVICE_FAMILY = 1,2,7`）。
iPad を対象に含めると **iPad用スクリーンショットが必須**になり、iPadでの表示崩れが
リジェクト理由にもなります。本アプリは縦持ちiPhone前提の設計なので、絞るのが安全です。

- Xcode → TARGETS → General → **Supported Destinations** から
  iPad / Apple Vision を削除し、**iPhone だけ**にする

**0-3. 輸出コンプライアンスの申告を省略する（5分）**

未設定だと**アップロードのたびに暗号化の質問**が出ます。本アプリは独自暗号を
使っていないため、Info に以下を追加すれば以後スキップされます。

- キー: `ITSAppUsesNonExemptEncryption` / 型: Boolean / 値: **NO**

**0-4. バージョン番号（5分）**

- General → Identity → **Version = 1.0.0** / **Build = 1**
- 以後アップロードのたびに Build を +1（1.0.0 のまま Build だけ上げる）

**0-5. スクリーンショット撮影（半日）**

§5 の6枚構成で、**6.9インチ（iPhone 16 Pro Max）シミュレータ**で撮影します。
このサイズを入れておけば、小さい端末サイズには自動で流用されます。

- シミュレータで ⌘S → デスクトップに保存
- Proのデコを見せたい場合は、ペイウォールの「デバッグ切替」でPro状態にしてから撮影

**0-6. Privacy Manifest をターゲットに追加（10分）★必須・見落とし注意**

Xcode のプロジェクトナビゲータへドラッグし、**Target Membership に `ColorHunt`
をチェック**してください。

### 詰まりやすいポイント

| 症状 | 原因 |
|---|---|
| 購入画面に価格が出ない | 製品IDの不一致 / **Step 2 の有料App契約が未完了** |
