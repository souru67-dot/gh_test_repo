## 先に知っておくと迷わないこと — Xcode の左ペインは「取り込んだ時点の一覧」

`.xcodeproj` はリポジトリの外にあり、リポジトリのフォルダを**参照として**
プロジェクトに置いた構成です（`ARCHITECTURE_iOS.md` §6 の負債表にある通り）。
Xcode はファイルを1つずつ参照として記録するので、性質はこうなります。

| | どうなるか |
|---|---|
| 既にあるファイルの**中身が変わった** | 参照先の実ファイルを読むので**常に最新**。何もしなくてよい |
| **新しいファイルが増えた** | 左ペインに**自動では現れない**。手で追加が必要 |

なので「左ペインの `docs` に見えるファイルが、実際のリポジトリより少ない」と
いった食い違いは**正常**で、ビルドには影響しません。取り込んだ日より後に
増えたファイルが並んでいないだけです。

**影響が出るのは、新しく増えたファイルをビルドに含めたいときだけ**です。
このドキュメントの A がまさにそれ（`PrivacyInfo.xcprivacy` は後から作られた
ファイル）で、今後も新規ファイルが増えたときは同じ手順が要ります。

### 参照先が正しいかの確かめ方（30秒）

見た目のツリー構造ではなく、実ファイルの場所だけ見れば十分です。

1. 対象のファイルを左ペインで選択
2. **⌥⌘1**（File Inspector）を開く
3. 一番下の **Full Path** を見る

`AppState.swift` でも同じことをして、**2つの Full Path の親フォルダが
一致していれば正解**です。一致していなければ、Mac 上にクローンが2つあって
別々の場所を掴んでいます。

## A. Privacy Manifest を Xcode に追加（10分）

### なぜやるのか

これが無いと、アプリをアップロードした瞬間に Apple から
**「ITMS-91053: Missing API declaration」**というエラーで弾かれます。
2024年5月から必須になったルールです。ファイルはこちらで作成済みなので、
Xcode に「このファイルもアプリに含めてね」と教えるだけの作業です。

### 手順

1. **Xcode で ColorHunt のプロジェクトを開きます。**

2. 左側のファイル一覧（プロジェクトナビゲータ）を表示します。
   見えていなければ **⌘1** を押してください。

3. 一覧の中から `AppState.swift` を探して**右クリック → Show in Finder**。
   Finder が開き、Swift ファイルが並んだフォルダが表示されます。
   ここが `iosApp/ColorHunt/` です。

4. 同じフォルダの中に **`PrivacyInfo.xcprivacy`** があるはずです。
   > 見当たらない場合は、リポジトリを最新にしてください（`git pull`）。

5. その `PrivacyInfo.xcprivacy` を、**Finder から Xcode の左側の一覧へ
   ドラッグ&ドロップ**します。落とす場所は `AppState.swift` のすぐ近くでOKです。

6. `Choose options for adding these files:` というダイアログが出ます。
   **ここが一番大事です**。

   **Xcode 16 以降**（Action というプルダウンが出る新しい形）:

   | 項目 | 設定 |
   |---|---|
   | Action | **Reference files in place** |
   | Targets: **ColorHunt** | **チェックを入れる** |

   Action の3択はそれぞれこういう意味です。

   | 選択肢 | 何が起きるか |
   |---|---|
   | Copy files to destination | ファイルが**複製**され、Xcode 側のコピーがビルドに使われる。リポジトリ側を更新しても反映されず、git にも残らない |
   | Move files to destination | リポジトリから**ファイルが消える**。git 上は削除扱い |
   | **Reference files in place** | リポジトリのファイルをそのまま参照。更新がそのまま反映され、履歴も残る |

   リポジトリのフォルダをそのままプロジェクトに置いている構成なので、
   Swift ファイルたちと同じ「参照」の形に揃えるのが正解です。

   **Xcode 15 以前**（チェックボックスの古い形）:

   | 項目 | 設定 |
   |---|---|
   | Destination: Copy items if needed | **チェックを外す**（＝上の Reference files in place と同じ意味） |
   | Added folders | Create groups |
   | Add to targets: **ColorHunt** | **チェックを入れる** |

   > どちらの形でも、**Targets / Add to targets の `ColorHunt` が本命**です。
   > この作業の目的は「このファイルをアプリのバンドルに含める」ことなので、
   > ここが外れていると追加した意味がありません。

7. **Finish** をクリック。

### できたかの確認

1. 左の一覧で、一番上の青いアイコン（プロジェクト名）をクリック
2. 中央の **TARGETS → ColorHunt** を選択
3. 上のタブから **Build Phases**
4. **Copy Bundle Resources** の三角を開く
5. リストの中に **`PrivacyInfo.xcprivacy`** があれば成功です

### うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| Copy Bundle Resources に無い | 手順6で「Add to targets」のチェックを忘れています。ファイルを選んで右側の **Target Membership** で `ColorHunt` にチェック |
| ファイルが赤字で表示される | 参照先が見つかっていません。一度削除（Remove Reference）して手順5からやり直し |
| ビルドが `Multiple commands produce` で失敗 | 二重に追加されています。一覧で同名ファイルが2つ無いか確認し、片方を Remove Reference |

## B. サポート/プライバシーページを公開（1時間）

### なぜやるのか

App Store の申請画面には、**サポートURL** と **プライバシーポリシーURL** の
入力欄があり、どちらも**空欄では次に進めません**。ページの中身は用意済みなので、
インターネット上に置いてURLを作る作業だけです。

**ターミナルは使いません。**ブラウザだけで完結する手順にしています。

### 事前に知っておくこと

- 置き場所は **GitHub Pages**（無料）を使います
- **リポジトリは必ず Public（公開）にしてください。** Private だと GitHub Pages が
  有料プラン限定になり、使えません
- 公開されるのは、これから作る新しいリポジトリに入れる**2つのHTMLファイルだけ**です。
  アプリのソースコードは公開されません

> ⚠️ **今のリポジトリ（gh_test_repo）をそのまま公開しないでください。**
> ビルド設定・リリース計画・売上目標などが全部見えてしまいます。
> 必ず新しい別のリポジトリを作ります。

### 手順

**B-1. 公開用のリポジトリを作る**

1. ブラウザで https://github.com を開いてサインイン
2. 右上の **＋** → **New repository**
3. 次のとおり入力します:

   | 項目 | 入力 |
   |---|---|
   | Repository name | `colorhunt-site` |
   | Description | 空欄でOK |
   | 公開範囲 | **Public** を選択（重要） |
   | Add a README file | **チェックを入れる**（重要） |

   > 「Add a README file」を入れないと中身が空になり、次の Pages 設定で
   > ブランチが選べなくなります。

4. **Create repository** をクリック

**B-2. 2つのファイルをアップロードする**

1. 作られたリポジトリの画面で **Add file** → **Upload files**
2. Mac の Finder で、リポジトリの **`site`** フォルダを開きます
   （`gh_test_repo/site/`）
3. 中にある **`index.html`** と **`privacy.html`** の2つを選び、
   ブラウザの点線の枠へ**ドラッグ&ドロップ**
4. 下までスクロールして **Commit changes** をクリック

**B-3. 公開設定をオンにする**

1. リポジトリ上部の **Settings**（歯車）
2. 左メニューの **Pages**
3. **Source** を **Deploy from a branch** にする
4. **Branch** を **main** / フォルダは **/ (root)** にして **Save**
5. **3〜5分待ちます**（すぐには表示されません。コーヒーを淹れてください）
6. 同じ Pages の画面を再読み込みすると、上部にURLが表示されます

### できたかの確認

以下の2つのURLをブラウザで開いて、ページが表示されればOKです。

```
https://souru67-dot.github.io/colorhunt-site/
https://souru67-dot.github.io/colorhunt-site/privacy.html
```

> **公開済み（2026-07-30）**。以降このURLをそのまま使います。

**スマートフォンでも開いて確認してください。** 審査担当者はスマホで見ることが
あります。文字が小さすぎたり横スクロールが出たりしないことを確認します。

確認できたら、この2つのURLを**メモに控えてください**。
`IOS_LAUNCH_GUIDE.md` の Step 5 で入力します。

### うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| Pages の設定で Branch が選べない | README を作らなかったため main ブランチが空です。B-2 のアップロードを先に済ませてください |
| 404 が出る | ①まだ数分経っていない ②リポジトリが Private ③URL末尾のスラッシュ抜け。この順で確認 |
| Pages の項目が Settings に無い | リポジトリが Private です。Settings 最下部の **Danger Zone → Change visibility** から Public に変更 |
| ページは出るが崩れている | ファイルを1つしか上げていない可能性。`index.html` と `privacy.html` の**両方**が必要です |

### あとで内容を直したいとき

メールアドレスや文面を変えたくなったら、GitHub上で該当ファイルを開き、
鉛筆アイコン（Edit）から直接編集して Commit するだけで反映されます。

## C. メモリ実測（30分）— 完了済み

> **2026-08-02 に実施し、合格しました**（iPhone 17 Pro・消費204MB）。
> 以下は次バージョンで測り直すときのための手順です。結果は
> `IOS_LAUNCH_GUIDE.md` §3.4 の記録表にあります。

### なぜやるのか

取り込んだ写真がメモリに載り続けると、古い端末では iOS に強制終了させられます。
落ちてもクラッシュログには何も残らず、ユーザーからは「突然落ちるアプリ」に
見えます。**v1.0 ではサムネイル分離により 718MB → 204MB まで下げ、iPhone 8
（上限約1.4GB）でも1.1GB以上の余裕を確保しました。**

### 手順

詳しい背景と判定基準は **`IOS_LAUNCH_GUIDE.md` の §3.4** にあります。
ここでは操作だけを書きます。

**C-1. 測定できる状態にする**

1. iPhone を Mac に USB 接続します
2. Xcode のメニュー **Product → Scheme → Edit Scheme…**
3. 左の **Run** を選択 → **Info** タブ
4. **Build Configuration** を `Debug` から **`Release`** に変更 → **Close**
5. iPhone から ColorHunt を**一度削除**します（長押し → Appを削除）

> なぜ Release にするのか: Debug のままだと実際より多くメモリを使うため、
> 不当に厳しい判定になります。

**C-2. 残りメモリを表示させる**

1. Xcode で `ColorHuntApp.swift` を開きます
2. ファイルの一番上、`import SwiftUI` の**次の行**に以下を追加:

   ```swift
   import os
   ```

3. 同じファイルの `final class AppDelegate: NSObject, UIApplicationDelegate {`
   （22行目あたり）の**次の行**に、以下を貼り付けます:

   ```swift
       func application(_ application: UIApplication,
                        didFinishLaunchingWithOptions options: [UIApplication.LaunchOptionsKey: Any]? = nil) -> Bool {
           let timer = Timer(timeInterval: 2, repeats: true) { _ in
               let remain = Double(os_proc_available_memory()) / 1_048_576
               print(String(format: "🧠 残り %.0f MB", remain))
           }
           RunLoop.main.add(timer, forMode: .common)
           return true
       }
   ```

   > **`.common` は必須です。** 既定のモードだとスクロール中にタイマーが
   > 止まります。ハント画面を一番下までスクロールしている最中こそメモリが
   > 一番厳しいので、そこで測れないと意味がありません。

   ### なぜ SwiftUI 側ではなく AppDelegate に置くのか

   ここは実機で2回失敗した箇所です。**同じ轍を踏まないでください。**

   | 試した書き方 | 何が起きたか |
   |---|---|
   | `Timer.publish(...).autoconnect()` を `.onReceive` で | Combine の API で、`ColorHuntApp.swift` は Combine を import していないため `Instance method 'autoconnect()' is not available` でビルドが止まる（Xcode 26 の MemberImportVisibility。`AppState.swift` の冒頭コメント参照） |
   | 上を `.task { while ... }` に置き換え | **新規インストールの初回起動でクラッシュ**。SwiftUI がビューツリーを組み立てる最中にスタックが溢れ、`EXC_BAD_ACCESS` で 5,500フレーム超（繰り返し単位に `_TaskModifier2` が含まれていた） |

   AppDelegate のタイマーは SwiftUI のビューツリーに一切触れないので、
   この種の副作用が起きません。**`#if DEBUG` で囲まないでください** —
   C-1 で Build Configuration を `Release` にしており、Release では `DEBUG` が
   定義されないため、囲むとコードごと消えて何も出力されません。

**C-3. 測る**

1. 実行先（画面上部）を接続した iPhone にして、**▶ を押します**
2. Xcode 下部にコンソールが出ます。2秒ごとに `🧠 残り ◯◯◯ MB` と流れます
3. iPhone で次の順に操作し、**表示される数字が一番小さくなった値**を控えます:

   | 順 | 操作 |
   |---|---|
   | 1 | 起動直後 |
   | 2 | ハント →「自動で仕分け」→ 取り込み完了まで待つ |
   | 3 | ハント画面を**一番下までスクロール** |
   | 4 | 20枚選んでコラージュ画面へ |
   | 5 | Proテンプレで保存（書き出し）する |

4. **アプリを完全に終了して、もう一度起動します**（アプリスイッチャーで上にスワイプ）
5. **ハント画面を一番下までスクロール**して、また数字を確認します

> ⚠️ **手順4〜5を飛ばさないでください。** 再起動直後は写真が読み込まれておらず
> 数字が低く出ます。スクロールし切った後の値が、実際に使っているときの値です。

### 判定

**一番小さかった「残り」の値**で判断します。

| 残り | 判定 | 次にすること |
|---|---|---|
| **500MB 以上** | 合格 🎉 | C-4 に進んで、そのままリリースへ |
| 250〜500MB | 条件付き合格 | リリースしてOK。v1.1 で改修 |
| **250MB 未満** | 不合格 | **提出前に改修が必要です。私に連絡してください**（半日程度の作業です） |

**C-4. 後片付け（忘れると後で困ります）**

1. C-2 で貼り付けた `func application(_:didFinishLaunchingWithOptions:)` を**削除**します
2. 追加した `import os` も削除します
3. **Product → Scheme → Edit Scheme… → Run → Build Configuration を
   `Debug` に戻します**

> 3番を忘れると、ブレークポイントが効かなくなり「デバッグできない」と
> 原因不明に悩むことになります。必ず戻してください。

## E. ペイウォールの審査用スクリーンショット（30分）

### なぜやるのか

App Store Connect で課金アイテムを登録するとき、**審査用スクリーンショットが必須**
です（`IOS_LAUNCH_GUIDE.md` §8 Step 4-1）。用途は宣伝ではなく、審査担当者に
**「アプリのどこで購入が起きるか」**を示すことです。ペイウォール画面が1枚あれば
足ります。

### 先に知っておくこと — いま撮ると「壊れた画面」になります

ペイウォールは製品情報を読めないとき、こう表示します。

```
※ 製品情報を読み込めませんでした（App Store Connect 設定後に有効）
```

App Store Connect にまだアプリが無い今の状態では、**必ずこの行が出ます**。
これが写ったスクショを審査に出すと、担当者には不具合に見えます。

回避策は2つあり、**承認前に終わらせたいなら E-1 の方法**を使ってください。

| 方法 | いつ撮れるか | 手間 |
|---|---|---|
| **E-1. StoreKit 設定ファイル**（下記） | **今すぐ** | 30分 |
| E-2. Sandbox で撮る | 承認後（Step 4-3 のついで） | 追加ゼロ |

E-1 は課金まわりをローカルで丸ごとテストできるようになるので、どのみち
やっておく価値があります（購入・復元の動作確認が Sandbox 無しでできます）。

### E-1. StoreKit 設定ファイルを作る

**新規ファイルは Xcode のテンプレートから作ってください。** そうすればプロジェクトへ
自動で登録され、このドキュメント冒頭の「左ペインは取り込んだ時点の一覧」問題を
踏まずに済みます。

1. Xcode で **File → New → File from Template…**
2. 検索欄に `StoreKit` と入力 → **StoreKit Configuration File** を選んで **Next**
3. 名前は `ColorHunt` のままでOK。保存先は `iosApp/ColorHunt/` フォルダ

   > **「Sync this file with an app in App Store Connect」にチェックを入れない**
   > でください。まだアプリが存在しないため失敗します。

   > **Targets の `ColorHunt` にもチェックを入れないでください。** これは開発用の
   > ファイルで、アプリに同梱するものではありません。

4. 作られた `ColorHunt.storekit` を開き、左下の **＋** →
   **Add Non-Consumable In-App Purchase**
5. 右側に次を入力します:

   | 項目 | 入力 |
   |---|---|
   | Reference Name | `ColorHunt Pro` |
   | Product ID | **`com.yk-dev.ColorHunt.pro`** |
   | Price | `¥800`（一覧から選択） |

   > **Product ID は1文字でも違うと価格が出ません。** これは
   > `AppState.swift` の `proID` と完全一致させる必要があります。
   > 迷ったら `AppState.swift` を開いて `proID` の行をコピーしてください。

6. さらに **Localizations** の ＋ で日本語を追加:

   | 項目 | 入力 |
   |---|---|
   | Display Name | `ColorHunt Pro` |
   | Description | `透かしを削除し、Pro限定テンプレート7種と2160pxの高画質書き出しが使えます` |

7. **Product → Scheme → Edit Scheme…** → 左の **Run** → **Options** タブ
8. **StoreKit Configuration** の欄で、いま作った `ColorHunt.storekit` を選択 →
   **Close**

### E-2. 撮る

1. シミュレータ（または実機）で実行します
2. コラージュ画面 → **王冠マークの付いたテンプレート**をタップ
3. 「保存」または「共有」をタップ → **ペイウォールが開きます**
4. **「※ 製品情報を読み込めませんでした」が消えて、`¥800` が出ていることを確認**
   - 出ない場合は Product ID の不一致か、手順8の選択漏れです
5. 撮影します
   - シミュレータ: **⌘S**（デスクトップに保存）
   - 実機: 音量アップ + サイドボタン → AirDrop で Mac へ

> **リサイズは不要です。** 6枚の宣伝用スクショと違い、こちらはサイズ指定が
> ゆるく（最低 640 × 920 ピクセル）、そのままのスクショで余裕を満たします。

### できたかの確認

- [ ] 画面に **`¥800`** と **「購入する」「購入を復元」** が写っている
- [ ] 「※ 製品情報を読み込めませんでした」が**写っていない**
- [ ] 「デバッグ切替」ボタンが写っていても構いません（Debugビルドのみの表示で、
      製品版には出ません）
- [ ] ファイルサイズが 640 × 920 ピクセル以上

このファイルは Step 4-1 の **「審査用スクリーンショット」**の欄にアップロードします。

### ついでにできること（おすすめ）

StoreKit 設定ファイルを選んだ状態では、**購入が実際に成立します**（課金は
発生しません）。`IOS_LAUNCH_GUIDE.md` §3.1 の「課金」チェックリストを、
承認を待たずにここで一通り流せます。

- 購入 → 透かしが消える・王冠とPROピルが消える・書き出しが2160pxになる
- 購入を復元 → 戻る
- Xcode の **Debug → StoreKit → Manage Transactions** で購入を取り消せば、
  無料状態に戻して何度でも試せます

### 終わったら

**Edit Scheme… → Run → Options → StoreKit Configuration を `None` に戻して
ください。** 戻し忘れても製品版のビルド（Archive）には影響しませんが、実機
Sandbox での確認（Step 4-3）が正しく動かなくなります。


## 全部終わったら

この4件が完了したら、`docs/IOS_LAUNCH_GUIDE.md` の **Step 1** に進んでください。
承認メールが届いていれば、そこから審査提出まで一本道です。

**詰まったら、遠慮なく聞いてください。** エラーメッセージやスクリーンショットを
そのまま貼っていただければ、原因を特定します。
