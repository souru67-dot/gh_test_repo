# 入力変換 (Input Transform) — 対応入力と精度

動画カラーパイプラインの前段に「入力変換」ステージを設け、各社の Log 素材を
Rec.709 に正規化してからクリエイティブ LUT を当てる。これにより、どの機材の
Log でも同じプリセットが同じ色の方向性で効く。

> **表記に関する注意 (景表法/優良誤認の回避):** 公開仕様の数式で実装したものだけを
> 「公式(数式準拠)」と記し、公開カーブが無い/非公開のものは「近似」と明示する。
> 「完全対応」「純正同等」といった表現は使わない。近似はメーカー純正の変換を
> 再現するものではなく、実用上のベースラインを与えるものである。

## パイプライン

```
[各社 Log / HDR 素材]
   │
   ▼  ① 入力変換 (Input Transform)   ← 本ドキュメントの対象
   │     Log → scene-linear (decode)
   │     色域変換 (S-Gamut3.Cine / BT.2020 → Rec.709)
   │     scene-linear → Rec.709 表示エンコード
   │     露出 ±2EV / コントラスト微調整(任意)
   ▼
[Rec.709 に正規化された信号]
   │
   ▼  ② クリエイティブ LUT (.cube) + 強度
   ▼
   ▼  ③ 簡易調整(露出・コントラスト・色温度 等)
   ▼
[焼き込み済み 3D LUT] ── プレビュー(ExoPlayer)/ 書き出し(Transformer)共通
   │
   ▼  ④ SNS セーフ書き出し(SDR / BT.709 / limited に正規化)
```

- ①〜③は `LutBaker.bake` が単一の 33³ 3D LUT に合成する。プレビューと書き出しは
  完全に同一の cube を使うため、見た目が一致する。
- HDR(HLG/PQ)素材はデコーダ/Transformer が先に SDR(709)へトーンマップするため、
  入力変換の Log decode は二重適用しない(EV/コントラストのみ適用)。

## 対応入力一覧

| 入力 | 精度 | 実装 |
|------|------|------|
| なし (Rec.709) | — | 恒等(既定)。既存プリセットの濃度は完全維持 |
| Sony S-Log3 / S-Gamut3.Cine | **公式(数式準拠)** | S-Log3 公開 decode 式 + S-Gamut3.Cine→709 マトリクス |
| Apple Log | **公式(数式準拠)** | Apple Log Profile 公開定数の decode 式 + BT.2020→709 |
| HLG (BT.2100) | **公式(規格準拠)** | デコーダの SDR トーンマップに委譲(二重適用回避) |
| 汎用 Log | 近似 | 未知 Log 向けの汎用対数 decode |
| DJI D-Log-M | 近似 | 汎用 Log を D-Log-M 相当のパラメータで近似 |
| S-Cinetone for Mobile | 近似 | Log ではなくピクチャープロファイル。軽い復元のみ(既存の見た目を維持) |
| OPPO / Xiaomi / vivo / Galaxy Log | 近似 | 各ベンダー向けにゲイン/ピボットを調整した汎用 Log 近似 |

## 自動検出と手動選択

- **自動検出:** コンテナ/コーデックのタグから確実に判別できるもののみ自動適用する。
  HDR(HLG/PQ)は HLG(トーンマップ委譲)、それ以外は「なし(709)」。各社 Log は
  メタデータに現れないことが多く、推測で誤った色にするより「なし」の方が安全。
- **Log 素材ヒント:** 代表フレーム1枚の輝度分布が中央に強く寄っている(フラットな
  Log 特有の分布)場合、「Log 素材の可能性があります」と表示し手動選択を促す。
- **手動選択:** 色タブ最上部の「入力」から選択シートを開く。各項目はグレーランプに
  変換を当てた簡易サムネイルと精度ラベル付き。**選択は素材ごとに記憶**する。
- **微調整:** 露出 ±2EV とコントラストで個体差・撮影露出のばらつきを吸収する。

## 既存プリセットへの影響(非回帰)

入力変換の既定は「なし(Rec.709)」であり、この場合 `LutBaker.bake` は従来経路と
**バイト単位で一致**する(`InputTransform.NONE` かつパラメータ恒等のとき、入力変換
ステージは完全にスキップされる)。したがって、既存の Faded Film / S-Cinetone 用
プリセット等の濃度・色は本変更で一切変わらない。ユーザーが明示的に入力変換を
選んだ素材でのみ、前段の 709 正規化が働く。

## 検証

数式・定数は `tools/lut_analysis/input_transforms.py` で検証する:

- S-Log3 / Apple Log(公式): グレーランプに対して単調・レンジ内(0..1)。
  S-Log3 の 18% グレー相当が 709 で ~0.44 付近へ収束。
- 汎用 Log / D-Log-M(近似): 単調性と概形のみ確認。
- 色域マトリクスは XYZ 経由で算出(S-Gamut3.Cine→709 / BT.2020→709)。

Kotlin 実装(`InputTransform.kt`)は Python リファレンスと ≤0.0001 で一致することを
確認済み。
